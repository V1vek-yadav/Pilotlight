Design proposal · v1

Pilotlight

A pilot light burns all day on almost no fuel. This app does the same for your Claude Code sessions. Each session gets one small light in the menu bar. The lights stay quiet while Claude works. When a session needs you, you can answer it right there or jump straight to that VS Code window. There is no chat panel, because VS Code already has one.

< 25 MBmemory target

What it does

Seven features in v1

Every feature has to answer one of two questions: does something need me? or take me there. Anything that doesn't answer either is left out.

working needs you done failed idle

Lights instead of text

One dot per session, with the ones that need you sorted first. You can tell how all your sessions are doing from the corner of your eye. If you'd rather have one dot, switch to “Single” for a single light plus a count.

Allow ⏎Deny ⌫Always A

Answer permission asks in place

Allow, deny, or save an “always allow” rule for that project, from the board or from the banner. If you don't answer within 30 s, the ask goes back to the normal VS Code prompt, so nothing is ever blocked for long.

123 → that exact VS Code window

Jump to VS Code for everything else

When Claude asks a question, finishes, or fails, one click or a number key brings its VS Code window to the front. You answer Claude in VS Code, where you can see the full context.

Added Redis rate limiting · +84 −12

One-line recaps

When a session stops, the hook saves Claude's last line and runs git diff --shortstat. You see what changed without opening anything, and it costs almost nothing to collect.

banner?not if you're already looking

Quiet by default

You get no banner if you're already in that window or the board is open. Banners for finished sessions only appear when you're working somewhere else. The default sound is one soft chime, or you can turn it off.

⌥Space⏎⌫A1–9esc

Works from the keyboard

⌥ Space opens the board. ⏎ and ⌫ answer the oldest ask, and 1–9 jump to a session. You can handle an ask without touching the mouse.

drag out of the menu bar · snap to any edge · pull one light out to pin it

Put the lights anywhere

Drag the lights out of the menu bar and they become a floating strip. Snap it to an edge, where it turns vertical on the sides, or pull a single light out to keep one session next to the code you're watching. Drop either one on the menu bar to dock it again. The strip dims when nothing needs you. This helps on external monitors, and on MacBooks where the notch hides menu bar icons once there are too many. It's one borderless NSPanel that shows on every Space and in full screen, needs no Accessibility permission, and uses no extra CPU when idle.

What I cut on purpose

Why it uses less than Vibe Notch

Most of an app's memory and idle CPU goes to keeping a second UI alive and in sync. Pilotlight doesn't have one.

CutWhyInstead
Chat in the notchA second chat needs a web view, has to parse the transcript, and has to keep state in sync. VS Code already has a full chat panel.Jump to the right window, with the Claude panel already focused.
Notch-only UIExternal monitors and older Macs have no notch. Drawing over it means keeping an overlay window open all the time.A standard menu bar item (NSStatusItem) that works on every display.
Live transcript / streamingIt means constant redraws and re-reading JSONL files.One activity line per tool call, plus a recap when the session ends.
Process scanningPolling wakes the CPU even when nothing is happening.Claude Code's own hooks send events to the app, and the app waits on a socket.
History & analyticsThey're nice, but storage and UI keep growing.A single line in the footer with today's count.

How it stays light

Driven by events, with nothing in between

The app and the hook are the same small Swift binary. When Claude Code runs it as a hook, it sends one line and exits. When you open it from Finder, it's the menu bar app.

Wiring

Which hook drives each light

Pilotlight registers 8 hook events in ~/.claude/settings.json, about half as many as Vibe Notch did, so there are fewer process launches. Menu bar lights are drawn as a still image, because macOS re-snapshots a status item on every frame of an animation. The breathing animation only runs in the floating strip.

HookLightWhat you see
SessionStart appearsA new ring. The project name comes from cwd, and the branch from .git/HEAD.
UserPromptSubmit blue, breathingThe session counts as working, and its timer starts.
PreToolUse—The activity line (“Editing auth.ts”) and one tick in the sparkline
PostToolUse—Clears an ask once you've answered it in VS Code
PermissionRequest amberAllow / Deny / Always. If you're already in that session's window, it steps aside immediately. Otherwise it waits up to 30 s, then hands the ask back to VS Code.
PreToolUse (AskUserQuestion), or a Stop whose last line is a question amber“Asked you something” plus the question, and a button to reply in VS Code
Stop greenA recap: Claude's last line and the diff stats
StopFailure redThe reason, for example 529 overloaded or a usage limit
SessionEndremovedThe light goes away.
Notification, Subagent*, PostToolUseFailure, Pre/PostCompact, PermissionDeniedNot registered in v1. Fewer events means fewer process launches.

Scope

Later, maybe, and never

Later, maybe

  • A small editor for per-project “always allow” rules
  • Sessions running in Terminal / iTerm and Cursor windows
  • Snooze an ask for 10 minutes
  • A light that follows its VS Code window around. It needs the Accessibility permission, so it's not in v1.

Never

  • A chat box, in any form
  • Showing token-by-token streaming
  • Anything that has to poll

Build plan

  • One Swift package with two entry points: the app, and pilot emit
  • An installer that adds the hooks next to the existing Vibe Notch ones, so both apps can run side by side while you switch over
  • Signed and notarized, with a Sparkle feed for updates

This is a mockup in a single HTML file, and everything above the fold is simulated. In the real app, the light is drawn natively by NSStatusItem, the board is an NSPopover, and banners come from UNUserNotificationCenter.
